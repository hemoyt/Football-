١ — ما هو مشروع GOT؟

GOT هو اختصار لـ Gateway of Goals — بوابة الأهداف. منصة ويب متكاملة تربط لاعبي كرة القدم بـ الأندية الرياضية.

الفكرة ببساطة:
اللاعب يسجّل في المنصة، يضع بياناته ومهاراته وفيديوهاته. النادي يسجّل أيضاً، يبحث عن لاعبين مناسبين، ثم يتواصل معهم مباشرة عبر المنصة.

المميزات الرئيسية
للاعب:
  • إنشاء بروفايل احترافي
  • إضافة مهارات بتقييم 0 – 100
  • رفع فيديوهات إبراز
  • إضافة تاريخ مسيرة كروية
  • قبول أو رفض طلبات التواصل
للنادي:
  • إنشاء حساب موثّق بوثيقة رسمية
  • البحث عن لاعبين بفلاتر متعددة
  • حفظ اللاعبين المفضلين
  • إرسال طلبات تواصل
  • عرض بروفايلات اللاعبين
٣ — التقنيات المستخدمة

المشروع يعتمد على تقنيات ويب كلاسيكية بدون أي فريمووك معقد — سهل الفهم والنشر.

🖥️ الواجهة الأمامية (Frontend)
HTML5
لغة بناء صفحات الويب. كل صفحة في المشروع هي ملف .html.
CSS3
تصميم وتنسيق الصفحات. المشروع يستخدم متغيرات CSS لضبط الألوان بسهولة.
JavaScript (Vanilla)
بدون مكتبات خارجية. يتعامل مع الـ API ويعرض البيانات.
Fetch API
يُرسل طلبات HTTP إلى الـ Backend دون إعادة تحميل الصفحة.
⚙️ الخلفية (Backend)
PHP 8+
لغة السيرفر. كل ملف .php في api/ هو نقطة نهاية ترد بـ JSON.
PDO (PHP Data Objects)
طريقة آمنة للتواصل مع MySQL. تحمي من SQL Injection.

٥ — قاعدة البيانات (schema.sql)

ملف db/schema.sql يحتوي أوامر SQL لإنشاء 11 جدولاً مترابطة.

#الجدولماذا يخزّن؟
1usersكل المستخدمين — البريد، كلمة المرور المشفّرة، الدور
2player_profilesالاسم، الجنسية، المركز، الطول، الوزن، الصورة
3player_skillsالسرعة، التسديد، التمرير... (0 – 100)
4player_career_historyالأندية السابقة، الأهداف، الأسيست
5player_videosفيديوهات الإبراز (رفع أو YouTube/Vimeo)
6club_profilesبيانات النادي وحالة التوثيق
7contact_requestsطلبات التواصل (pending / accepted / declined)
8saved_playersاللاعبون المحفوظون لكل نادٍ
9profile_views_logسجل مشاهدات البروفايل
10system_logsسجل كل الأحداث (للأدمن)
11notificationsالإشعارات لكل مستخدم
كيف تترابط الجداول؟
1جدول users: البريد + كلمة المرور المشفّرة + الدور = "player"
↓
2جدول player_profiles: الاسم + الجنسية + المركز + الصورة
↓
3جدول player_skills: السرعة=85، التسديد=70، التمرير=90...
↓
4جدول player_videos: رابط الفيديو + نوعه + عنوانه
الارتباط بين الجداول يُسمى Foreign Key — مفتاح أجنبي. يضمن أن لا بيانات يتيمة في قاعدة البيانات.
⚠️ مهم عند الاستيراد على Hostinger:
احذف السطرين: CREATE DATABASE IF NOT EXISTS gog_db; و USE gog_db; لأن Hostinger لا يسمح بإنشاء database عبر SQL — قاعدتك موجودة بالفعل.
٦ — ملف الإعداد (config.php)

أهم ملف في الـ Backend. موجود في api/config.php. يحتوي إعدادات DB + دوال مساعدة.

بيانات الاتصال بـ MySQL
// بيانات الاتصال بـ MySQL على Hostinger define('DB_HOST', 'localhost'); // دائماً localhost على Hostinger define('DB_NAME', 'u611715919_hemoytgot'); // اسم قاعدة البيانات define('DB_USER', 'u611715919_hemoyt2005at'); // اسم المستخدم define('DB_PASS', 'Hemoyt47005@'); // كلمة المرور
حدود رفع الملفات
define('MAX_PHOTO_SIZE', 5 * 1024 * 1024); // 5 MB للصور define('MAX_DOC_SIZE', 10 * 1024 * 1024); // 10 MB للوثائق define('MAX_VIDEO_SIZE', 500 * 1024 * 1024); // 500 MB للفيديوهات
الدوال المساعدة
الدالةماذا تفعل؟
getDB()تُنشئ اتصالاً بـ MySQL مرة واحدة وتُعيده في كل مرة — يوفّر الموارد
jsonSuccess($data)ترد بـ JSON ناجح: {"id": 5, "name": "Ahmed"}
jsonError($msg)ترد بخطأ: {"message": "البريد مستخدم مسبقاً"}
requireSession($role)تتأكد أن المستخدم مسجّل دخول وله الصلاحية — وإلا 401/403
logAction()تسجّل كل حدث في جدول system_logs
sanitizeFilename()تنظّف اسم الملف — تمنع هجمات Path Traversal
كيف يستخدم كل ملف API هذا الملف؟
أول سطر في كل ملف PHP: require_once '../config.php';

register-player.php — تسجيل لاعب جديد
1يستقبل: البريد، كلمة المرور، الاسم، تاريخ الميلاد، الجنسية، المركز...
↓
2يتحقق أن البريد غير مستخدم من قبل
↓
3يشفّر كلمة المرور بـ bcrypt باستخدام password_hash()
↓
4يُدخل سجلاً في users + سجلاً في player_profiles
↓
5يبدأ Session ويرد بـ JSON ناجح
login.php — تسجيل الدخول
1يستقبل: البريد + كلمة المرور
↓
2يبحث عن البريد في جدول users
↓
3يتحقق من كلمة المرور بـ password_verify()
↓
4يحفظ user_id و role في الـ Session
↓
5يرد بـ JSON فيه الدور (player/club/admin) لتوجيه الصفحة
me.php — من أنا؟
عند فتح أي صفحة، JavaScript يسأل هذا الملف: "هل أنا مسجّل دخول؟"
إذا كانت الـ Session موجودة → يرد ببيانات المستخدم.
إذا لم تكن → يرد بـ 401 ويوجّه JavaScript لصفحة الدخول.

١٣ — كيف تعمل الصفحات معًا؟

رحلة لاعب من التسجيل حتى حصوله على طلب من نادٍ:

1اللاعب يفتح player/register.html ويملأ الفورم
↓
2js/auth.js يرسل البيانات بـ fetch() إلى api/auth/register-player.php
↓
3PHP يحفظ البيانات في MySQL ويبدأ Session
↓
4JavaScript يحوّل اللاعب إلى player/dashboard.html
↓
5الداشبورد يطلب api/player/profile.php لجلب بيانات اللاعب
↓
6نادٍ يبحث في api/club/search-players.php ويجد البروفايل
↓
7النادي يرسل طلب تواصل عبر api/club/send-request.php
↓
8اللاعب يرى الإشعار في داشبورده ويقبل الطلب
مفهوم الـ Session
بعد تسجيل الدخول، PHP يحفظ user_id و role في الـ Session على السيرفر.
في كل طلب لاحق، المتصفح يرسل كوكيز الـ Session تلقائياً. PHP يتحقق منها بـ requireSession().
هذا يحمي الـ API — لا يقدر أحد يطلب بيانات دون تسجيل دخول.
مفهوم الـ JSON API
كل ملفات PHP ترد بـ JSON فقط، ليس HTML.
{ "id": 42, "full_name": "Ahmed Ali", "position_primary": "ST", "nationality": "Egyptian" }
JavaScript يأخذ هذا الـ JSON ويعرضه في صفحة HTML.

١٥ — الأمان في المشروع
🔒 تشفير كلمة المرور
password_hash() مع bcrypt. الكلمات لا تُخزَّن نصاً أبداً.
🛡️ حماية SQL Injection
Prepared Statements مع PDO. بيانات المستخدم لا تدخل SQL مباشرة.
🔑 Session Authentication
كل API تتحقق من الـ Session. اللاعب لا يصل لـ API الأدمن والعكس.
📁 تنظيف أسماء الملفات
sanitizeFilename() تمنع Path Traversal هجمات.
📏 التحقق من الملفات
PHP يتحقق الحجم الأقصى + نوع الملف (MIME) قبل الرفع.
👮 التحقق من الدور
requireSession('player') تتأكد الدور. النادي لا يدخل على API اللاعب الخاصة.
⚠️ تحسينات مستقبلية:
  • تفعيل HTTPS (مجاني على Hostinger عبر Let's Encrypt)
  • إضافة Rate Limiting لمنع الطلبات الزائدة
  • تغيير كلمة مرور الأدمن فور النشر
